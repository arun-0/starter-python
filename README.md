# starter-python

Starter for a uv-managed Python 3.14 application: `src/` layout, pytest, ruff, pyright, VS Code settings.

## Layout

```text
starter-python/
├── .editorconfig                  <---------------- editor-agnostic basics: UTF-8, LF, 2-space indent, final newline; CRLF for .bat/.cmd/.ps1
├── .gitattributes                 <---------------- git stores text as LF on every OS; .bat/.cmd/.ps1 stay CRLF
├── .gitignore                     <---------------- keeps .venv, caches, build output and .env out of git; lets the four .vscode files in
├── .python-version                <---------------- "3.14": the interpreter uv pins for this project; uv downloads it if missing
├── .vscode/
│   ├── extensions.json            <---------------- recommended extensions: Python, Pylance, debugpy, Python Environments, Ruff
│   ├── launch.json                <---------------- two debug configs: run the package as a module, or run the current file
│   ├── settings.json              <---------------- LF endings, autosave, .venv discovery, pytest on, Ruff as formatter with fix-on-save
│   └── tasks.json                 <---------------- Terminal > Run Task: uv sync --locked, pytest, ruff check, pyright
├── README.md                      <---------------- this file
├── pyproject.toml                 <---------------- metadata, dev-tool bounds, console script, ruff/pytest/pyright config, uv_build backend
├── uv.lock                        <---------------- exact pinned versions for every OS; committed; never edited by hand
├── src/
│   └── python_project/            <---------------- the package; rename it together with the project
│       ├── __init__.py            <---------------- greeting() and main(); main() is the console-script entry point
│       └── __main__.py            <---------------- makes `python -m python_project` work; calls main()
├── tests/
│   └── test_python_project.py     <---------------- pytest tests; found through testpaths in pyproject.toml
│
├── .venv/                         <---------------- generated by uv sync, ignored: the project's own interpreter and packages
├── .pytest_cache/  .ruff_cache/   <---------------- generated by the tools, ignored; removed by `pyclean --debris all`
└── dist/                          <---------------- generated by uv build, ignored: the sdist and the wheel
```

## Start a new project from this template

1. Clone it.
2. Rename the project/package. Every occurrence to change:

   ```bash
   grep -rn --exclude-dir=.git --exclude-dir=.venv -e python-project -e python_project .
   ```

   Then rename the folder `src/python_project` to match.
3. Refresh the pinned dev tools to the newest versions the bounds allow, and install:

   ```bash
   uv lock --upgrade && uv sync
   ```

4. Check everything runs:

   ```bash
   uv run pytest && uv run ruff check . && uv run pyright
   ```

## What "template repository" means

- A GitHub setting, not a git concept: Settings → General → **Template repository**. Any repo can be
  switched to a template, or back, at any time. Projects already generated from it are unaffected.
- **Use this template** copies the files of the default branch verbatim into a new repo with a single
  root commit. No history, no parent commit, no git link back to the template.
- Not copied: issues, pull requests, wiki, releases, settings, branch protection, Actions secrets,
  collaborators, topics, and the template flag itself.
- Nothing inside any file is substituted. That is why step 2 above renames `python-project` by hand.
- GitHub shows "generated from ..." on the new repo. It is a label only; deleting or un-templating
  the source does not touch generated projects.

## Version policy

- `uv.lock` pins exact versions and is committed. `uv sync` installs exactly those, on every OS.
- The allowed ranges live in `pyproject.toml`. `uv lock --upgrade` moves within them and never past them.
- To take a new major of pytest or a new minor of ruff, widen the bound in `pyproject.toml` on purpose, run `uv lock`, run the checks, commit both files.

## Cleanups

See what is lying around before cleaning. Lists every untracked file, ignored or not, but collapses
any folder that is entirely untracked to its path, at whatever depth. So `.venv/` prints as one line,
`src/python_project/__pycache__/` prints as that path, and `src/` itself never prints because it holds
tracked files. Add `--exclude-standard` to drop the ignored ones and see only what git would commit.

```bash
git ls-files --others --directory
```

Remove tool and build debris, keeping the environment:

```bash
uvx pyclean .                  # cleans Python bytecode (pycache)
uvx pyclean . --debris all     # as well cleans ruff pytest and many other debris
```

Full cleanup, back to the state of a fresh clone:

```bash
uvx pyclean . --debris all && rm -rf .venv && uv cache prune
```

- `--debris all` also removes `dist/`, `build/` and `*.egg-info` left by `uv build`.
- `rm -rf .venv` drops the environment. `uv sync` recreates it from `uv.lock`.
- `uv cache prune` removes cache entries no project on this machine uses. Global and safe.
- `uv cache clean` is the bigger hammer: it deletes uv's whole cache, which is global: the wheels every
  project's `.venv` was hardlinked from, index metadata, and the `uvx` environments. Existing `.venv`s keep
  working; the next `uv sync` or `uvx` anywhere re-downloads. Only when disk space matters.

## Full build

From a fresh clone or after a full cleanup. Every step exits non-zero on failure, so the chain stops
at the first problem:

```bash
uv lock --check \
  && uv sync --locked \
  && uv run ruff format --check . \
  && uv run ruff check . \
  && uv run pyright \
  && uv run pytest \
  && uv build \
  && uv run python-project \
  && uv pip check
```

What each step proves:

- `uv lock --check`: `uv.lock` matches `pyproject.toml`. Fails if dependencies were edited without re-locking.
- `uv sync --locked`: creates `.venv` from the lock, exactly. Downloads Python 3.14 if it is missing.
- `uv run ruff format --check .`: code is formatted. `uv run ruff format .` fixes it.
- `uv run ruff check .`: lint, including import ordering. Add `--fix` to apply safe fixes.
- `uv run pyright`: type check.
- `uv run pytest`: tests.
- `uv build`: sdist and wheel into `dist/`, using the `uv_build` backend.
- `uv run python-project`: the console script from `[project.scripts]`. The module form is
  `uv run python -B -m python_project`.
- `uv pip check`: the installed packages are mutually compatible.
